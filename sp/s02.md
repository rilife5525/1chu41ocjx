## 7. 敵人／Boss
```ts
EnemyDef = { id,name,hp,r,spd,score,exp,ai,size, ground?,mid? }
BossDef  = { id,name,title,hp,r,art,color,quote }
THEME_PAL 每組欄位固定為 { h1, h2, ac, gl }。母專案 0~5 已佔用；
           你的專案要寫「0~5 佔位（照抄母專案數值即可）＋ 6~11 你自己的 6 組」共 **12 組**，
           合併時維護者只取 6~11。索引＝StageDef.theme（你的關卡用 6~11）。
```
新增敵人同步三處：`ENEMIES[key]`、`enemyDraw.DRAW[key]`、`enemyAI` 的 case。
新增 Boss 同步：`BOSSES`、`bossAI`、`bossDraw`。`art` 是設定圖索引（0~5 已佔用，見 §10）。
AI 名稱只有這些（母專案既有；**不得增刪改**）：
```
straight sine swoop hover spinner heavy dive turret mine
sniper laser ghost carrier aegis orbit mid
```
**你自己的 AI／Boss／中王／事件一律走擴充點，不要動上面的既有值**（§3.11）：
- 新 `ai` → 寫進 `CUSTOM_AI`（鍵＝你自訂的字串，`EnemyDef.ai` 直接填它）
- 新 Boss → `BossDef.id` 用你自己的編號，招式寫進 `CUSTOM_BOSS`
- 新中王 → `StageDef.mid` 用你自己的字串鍵，行為寫進 `CUSTOM_MID`
- 新環境事件 → `StageDef.events`／`TEvent.event.name` 用你自己的字串鍵，寫進 `CUSTOM_HAZARDS`
**⚠ 敵人 id 前綴 ＋ `ENEMY_ALIAS`（不做會靜默壞掉）**
你的敵人 id 一律加 `<code>_` 前綴，**包含骨架那 18 種基礎敵人**（`scout`→`<code>_scout` … `mid_cruiser`）。
但宿主檔 `engine/enemyAI.ts`／`bossAI.ts`／`hazards.ts` 是**照抄母專案**的，裡面用基礎詞彙呼叫
`g.spawnEnemy("scout" | "dart" | "kami", …)`——那些檔案不能改。所以你要在 `data/enemies.ts` 的
`ENEMY_ALIAS` 把詞彙對到你的 id：
```ts
export const ENEMY_ALIAS: Record<string, string> = {
  scout: "<code>_scout", dart: "<code>_dart", kami: "<code>_kami",
};
```
沒填的後果**不會報錯**：`carrier` 放不出護衛、Boss 的飛鏢彈幕空掉、`torpedo` 事件放不出自爆機。
（`StageDef.pool`／`heavy`／`mid` 是資料，直接寫你的 id，不需要別名。）
## 8. 裝備／卡片
```
SlotId  = weapon, armor, engine, core, chip, emblem
StatKey = atk, hp, spd, cd, ult, crit, exp, coin, rate, drop
Rarity  = R, SR, SSR, UR
EquipItem = { id,slot,rarity,lv,name,icon, main:{stat,v}, subs:{stat,v}[], proc?,locked? }
CardDef   = { id,name, desc:(n)=>string, rarity:0|1|2, max,icon,weight, apply:(g,n)=>void, skill?:SkillKey }
```
固定資料表：`SLOT_INFO`、`STAT_INFO`、`RARITY_INFO`、`PROCS`、`CARDS`。
固有技＝`PROCS` 資料（`ProcDef`，見 §3.8）＋ `equipProcs` 的 case。
`PROCS: Record<string, ProcDef>` ← 是「**以 id 為鍵的物件**」，不是陣列。
卡片 `apply(g, n)` 一律改 `g.p.s.<欄位>`（欄位清單見 §3.6），禁止自創數值容器。
## 9. 音樂／音效
```ts
Theme = {
  bpm:number; root:number;            // MIDI 根音
  scale:number[]; prog:number[];      // 音階（半音）／每小節和弦根音（音階度數）
  bassPat:number[]; arpPat:number[];  // 各 16 格
  kick:number[];                      // 16 格
  hat:number;                         // 0 無 / 1 閉 / 2 開   ← 是數字，不是陣列
  lead:boolean;                       // 有無旋律聲部        ← 是布林，不是陣列
}
```
`hat` 與 `lead` 的型別**最常被寫錯**（寫成陣列不會報錯，只是鼓與旋律整首消失）。
固定音樂索引：`0 選單 / 1 關卡 / 2 關卡變奏 / 3 Boss`。新專案要多一首從 **4** 起接續，不得插入或改動 0~3。
## 10. 資源與槽位配額（防撞）
以下每一項撞到**都不會報錯**，只會靜默顯示錯內容——這正是必須照抄的理由。
`<code>`＝你專案的 2~4 字母代號，須與母專案已佔用者不同（`a b c d e f 1 2`），並在交付說明標明。
| 用途 | 張數 | 打包方式 |
| --- | --- | --- |
| 關卡背景 | 6 | 六種 `BgKind` 各一張（`bg_<kind>.jpg`） |
| 機體立繪 | 2 | 每張 **3 格等寬** → 6 台（`pilots_<code>a.jpg`／`pilots_<code>b.jpg`） |
| 奧義背景 | 1 | **3×2 共 6 格**（`ult_atlas_<code>.jpg`） |
| Boss 設定圖 | 1 | **3×2 共 6 格**（`boss_sheet_<code>.jpg`） |
| **合計** | **10** | |
```
立繪       自帶圖集 assets/pilots_<code>.jpg（每張 **3 格等寬**，一格＝1080×1920 的 9:16），
           在 assets.ts 註冊圖集；ShipDef.portrait 填 {sheet:<代號>,col:0|1|2,focus,focusX?}
           ← 缺鍵／col 越界不報錯，只顯示空白框
奧義背景   自帶圖集 assets/ult_atlas_<code>.jpg（**3×2 共 6 格**，奧義全螢幕背景）
           ← 缺鍵不報錯，奧義背景全黑
敵人 id    加前綴 <code>_（含 18 種基礎）      ← 撞鍵＝其中一邊的 ENEMIES 條目被靜默吃掉；
                                                 改 id 後**必須填 `ENEMY_ALIAS`**（§7），
                                                 否則不會報錯、只是空轉
關卡 theme 從 6 起（母專案 0~5）               ← 合併時 THEME_PAL 要同步擴到 12 組（§7），
                                                 否則 theme % THEME_PAL.length 會把 6~11 繞回 0~5
音樂索引   從 4 起（母專案 0~3）               ← 撞到會被 clamp，播錯曲
Boss 設定圖 自帶 boss_sheet_<code>.jpg（母專案 3×2 的 art 0~5 已滿）
子彈樣式槽 從 170 起（見下方槽位表）           ← 撞號＝兩邊子彈外觀互蓋，不會報錯
背景／圖示配額見 §6／§3.5
```
**子彈樣式槽位表**（決定 `EXT_BASE_<代號>` 的值，見 §5）：
```
母專案已佔  23~64（EXT_BASE） 75~89（AR） 90~106（PL） 107~114（ZX）
            115~125（SG） 126~132（NX） 133~148（A） 153~156（SV）   共 118 條
零散空隙    65~74、149~152（皆 <10 條，不要用）
你的專案    從 170 起
```
素材一律經 `assets.ts` 註冊，不得在元件裡寫死路徑（`vite-plugin-singlefile` 會把 `import` 的圖轉 base64）。
