# 跨專案內容擴充契約

**使用前提**：模型只看得到本文件，看不到任何既有專案。因此本文件是唯一的規格來源。
本專案產出的**機體／關卡／敵人／Boss／裝備／卡片／音樂**，必須能在**零改動**下搬進母專案。

**對齊版本**：2026-10-25（母專案 SP 實測：**92 台機體**、44 種敵人、17 個固有技、28 張卡片、
12 組關卡配色、36 首曲、**368 條技能**、**92 張立繪**、我方子彈樣式已佔到 **style 560**）。
本文件所有「已佔用／已保留」的數字都是掃描值，不是估計——
看到數字對不上時，以 `SP/src` 為準並回頭修本檔。

## 1. 鐵則

1. **宿主介面凍結**：`Game`／`Player`／`Enemy`／`PBullet`／`EBullet`／`Beam`／`FxSys`／`PAL`／`audio`／     
   `sprites`／`shipUtil`／`patterns`／`constants` 只能照 §3 的簽名呼叫，不得新增、刪除、改名、     
   改參數順序或預設值。**自創＝搬移時必須寫一層轉接層，等於做白工。**
2. **禁止自創容器**：只有 `g.en.items`／`g.eb.items`／`g.pb.items`／`g.pk.items`／`g.beams.items`。     
   **沒有** `g.enemies`／`g.pickups`／`g.player`／`g.zones`。宿主沒有的東西查 §3.9 用既有 API 組合。
3. **資料驅動**：新增內容＝資料＋既有 register/case，不為單一內容建平行系統。固定名稱（schema、欄位、     
   key、index 語意、SFX／AI／事件名稱）皆為跨專案 API，不得改。
4. **宿主檔照抄、內容檔自創**（本條最容易做反）：
   - **宿主檔 → 逐字照抄骨架，不要重寫**：`Game.ts`／`renderer.ts`／`sprites.ts`／`shipUtil.ts`／       
     `input.ts`／`entities.ts`／`assets.ts`／`save.ts`／`types.ts`／`index.css`／`ui/*.tsx`。       
     骨架裡這些檔**就是母專案的實際檔案**——抄它才是可搬移的唯一做法。
   - **內容檔 → 只抄結構與接線，血肉一律自創**：`game/skills/<key>.ts`、`game/render/shipDraw<X>.ts`、       
     `game/data/*.ts` 條目。骨架裡這些是**佔位**（`placeholderShip()`／`/* …自創… */`），       
     不是範本。六台的招式結構讀起來一樣＝退回重做。
   - 本文件（`newship.md`）只給「介面與限制」，**刻意不附任何機體程式碼**。
5. **不要把內容寫死在引擎或 UI 裡**。註解與 UI 文案用繁體中文（台灣用語）；識別字用英文。
6. **遊戲名與首頁文案只能寫在 `game/data/brand.ts`**：`App.tsx`／`ui/MainMenu.tsx`／`main.tsx`
   已經一律讀 `BRAND`，**不要改這三檔裡的標題字串**（改了＝搬不回去）。骨架的 `brand.ts` 是
   「【你的遊戲名】」這種明顯佔位 → **整檔改寫成你自己的名字、副標、標語、跑馬燈**（§3.12）。

7. **命名與文案有固定格式**（§13）：駕駛英文名一律「名 姓」且不全大寫、`role` 用全角「｜」分隔、
   技能／奧義名的間隔符統一「・」、中文名不得與母專案重複且避開字型不支援的罕字。
   **格式不一致不會報錯**，只會讓整批看起來很亂，最後只能人工重掃——這種債不要留。

> 維護者注意：**不要**加回「骨架」「範例」「參考寫法」。歷史上附過一次 `fire()` 骨架，結果六台機體的>   
> `fire()` 開頭逐字相同（`const p = g.p, k = p.k, wl = g.lvl("weapon"), tier = evoTier(wl);`）。

新增欄位的語意（**只能讀，不要自己寫**——寫了會被引擎覆蓋或造成跨局洩漏）：

- `Player.tier`（0~3 進化階）／`gear`（六槽稀有度）／`procs`（固有技計時）／`ultBusy`（cut-in 剩餘）
  是引擎維護的顯示狀態；`focus`（低速鍵）／`still`（近乎靜止秒數）／`od`（過載增益秒數）
  是「來源引擎靠它分流」的輸入旗標，kit 只讀不寫。
- `Enemy.uid`＝物件池唯一序號。**per-enemy 狀態一律比對 `uid`**，不可拿 `Enemy` 物件當 WeakMap
  key（池會重用 → 上一隻的狀態跟著跑）。
- `Enemy.tl`＝由關卡時間軸生成（計入擊墜率分母）；`allyT`＝友軍化剩餘秒（>0 時不跑 AI、玩家子彈穿過）；
  `fzN`／`fzCd`／`fzWin`＝凍結抗性（唯一來源 `engine/freezeResist.ts`，kit 不得改）。
- `PBullet.selfMove`＝1 表示 kit 在 `updateBullet` 內自行位移、引擎跳過整合位移。
  **只有「來源引擎本身就是自走型」才可設**；一般 `kind>=20` 設了會讓主武整組停在原地。
- `EBullet.cz`＝port/008 血統旗標（由引擎蓋章，kit 不得自己設）。

機體私有狀態**只能**放 `g.p.k`（`init` 裡建）。  
敵機私有狀態**禁止**直接掛 `e.xxx`（物件池會跨局洩漏）；需要時用 `WeakMap<Enemy, 你的狀態>`。

`Player.s`（`PStats`）＝**卡片與裝備唯一可改的數值表**。卡片的 `apply` 一律寫 `g.p.s.<欄位>`：

```
atk rate spd pierce extra crit critDmg homing explode chainHit burn slowHit
options magnet luck coinMul expMul dropMul grazeMul killHeal shieldRegen revive
overload comboWin cdMul ultMul vigor
```

**禁止**自創 `g.mods`／`g.stats` 之類的新容器——不會報錯，但卡片效果會全部失效。

### 3.10 型別落點與結構凍結（`types.ts` 禁改）

`types.ts` 是共用型別的唯一落點，但它的**結構完全凍結**：不得增刪任何 `interface` / `type` / `const`  
的結構，**只允許修改下列純資料值**：

| 允許改             | 說明                                                     |
| --------------- | ------------------------------------------------------ |
| `ShipId` 的字串值   | 換成新機體 ID                                               |
| `SHIP_IDS` 陣列元素 | 同步新 ID                                                 |
| 其他純資料值          | 如 `ShipDef` 的 `color`／`name`（`ShipDef` 的**定義**不在本檔，見下） |

**具體禁止（違反任一條＝結構破壞，需還原後重出）：**

- 不得在 `types.ts` 新增任何 `interface`。`ShipDef`／`SkillInfo`、`Player`、    
  `Enemy` 等一律不放這裡，放母專案各檔案的位置：
  - `ShipDef`／`SkillInfo` → `data/ships.ts`（型別名**沿用 `SkillInfo`**，不得改名為 `SkillDef` 等）
  - `Enemy` 及實體（`PBullet`／`EBullet`／`Beam`／`Fx`／`Pickup` 等） → `entities.ts`
  - `Player` → `engine/player.ts`
- 不得把 `SkillLv` 改成 `Record<SkillKey, number>`，保持 `interface SkillLv` 原形狀。
- 不得刪 `SaveData`、`StageRecord`、`SkillLv`、`QualitySetting`。
- 不得在 `types.ts` 加 `import type { Game } from ...`（`Game` 是執行期類，不是型別來源）。

**同一條凍結延伸到其他內容型別**（定義位置見 §3.8；只准改值，不准改欄位名或型別）：

- `StageDef`／`TEvent`／`SpawnOpt`（`data/stages.ts`）：`boss` 必須是 **BOSSES 的數字索引**、    
  `music` 是 **THEMES 的數字索引**、`theme` 是 **THEME_PAL 的數字索引**、`reward` 是**數字**、    
  敵人 `size` 是**像素**（不是倍率）。也不得自創 `BgKind`／事件名（§3.8／§6）。
- `EnemyDef`／`BossDef`（`data/enemies.ts`）：`id` 是 `enemyDraw.enemySprite` 的繪製詞彙、    
  `ai` 必須是 `enemyAI.ts` 既有的值；`art` 必須是自有 `boss_sheet` 的格位索引。
- `ProcDef`（`data/equipment.ts`）：新增固有技必須**同時**改三處——`PROCS`、    
  `engine/equipProcs.ts` 的 `run()` switch、以及 `updateProcs()` 內的 `needTarget` 清單    
  （攻擊型才需目標）。漏改**不會報錯**，只會靜默失效（招式不出現／沒目標也放）。
- `Theme`（`audio.ts`）：欄位與型別不得改，只改數值；`THEMES` 數量可增（索引自 §10 起算）。

### 3.11 擴充點：**既有 case 不得修改，只能追加**（本節最重要）

引擎的行為詞彙（敵人 AI、彈幕、環境事件、Boss 招式）**與母專案共用**，所以：

- **既有 case／函式一律不得修改、不得刪除、不得改簽名。**（改了＝母專案所有機體一起壞掉，且不會報錯。）
- 要新行為 → 寫進下列 **`CUSTOM_*` 物件**，鍵名就是你資料裡要填的字串／索引。
  引擎已經接好派發：**母專案找不到的鍵會自動落到你的 `CUSTOM_*`**，既有 case 完全不受影響。
- 搬移＝把新增的那幾個條目**整段複製回母專案**（衝突只會落在同一個物件內，一貼就好）。

```ts
// game/engine/enemyAI.ts —— EnemyDef.ai 填自己的鍵
export const CUSTOM_AI: Record<string, (g: Game, e: Enemy, dt: number) => void> = {
  my_weaver: (g, e, dt) => { /* … */ },
};

// game/engine/bossAI.ts —— BossDef.id 填自己的索引；中王用 mid 字串鍵

export const CUSTOM_HAZARDS: Record<string, {
  start: (g: Game) => void;
  update: (g: Game, h: Hazard, dt: number) => void;
  end?: (g: Game) => void;
}> = {};
```

**自訂彈幕單元**：寫在 `engine/patterns.ts` 的**追加區**（`rndX()` 之後）。
約定：簽名一律 `(g: Game, x, y, …)`，只透過 `g.spawnEB`／`g.addBeam` 發射，回傳 void。
由你自己的 `CUSTOM_AI`／`CUSTOM_BOSS`／`CUSTOM_MID` 呼叫。

> ⚠ 兩條最容易做反的事：
> ① 去改 `patterns.ts` 既有函式的參數（例如讓 `ring()` 多收一個角度）→ 母專案所有敵人一起歪。
> ② 把新 AI 直接塞進 `updateEnemy` 的 `switch` 裡 → 搬移時會和母專案的 `switch` 打架。
> 追加區與 `CUSTOM_*` 就是為了讓你**永遠不必碰既有 case**。

- 最多兩段，用**全角直線「｜」（U+FF5C）**分隔，前後不加空格：`role: "高速連鎖｜擦彈爆發"`。
- 禁止 `／`、`/`、`・`、`．`、半角 `|`、`、`、`＋` 當分隔符。
- 單段就寫單段（`role: "高速機動"`），不要為了湊格式硬加第二段。

### 13.3 技能與奧義名的間隔符

- 要寫「主體・型態」時，**只用「・」（U+30FB）**：`涅槃・不死鳥`、`天啟・鎖定審判`。
- 禁止 `．`（U+FF0E 全角句點）、`·`（U+00B7）、`•`、`‧`、`･`（U+FF65 半角）。
  這些字在不同字型下寬度與基線都不同，混用會讓卡片與 HUD 排版看起來歪。
- 同一台機體的四個技能名，用不用「・」也要一致（不要三個用、一個不用）。

### 13.4 中文名的用字

- **不得與母專案任何既有名字相同或高度相似**（機體名／駕駛名／星紋名／技能名；清單見
  `newship禁用名單.md`）。重複**不會報錯**，只會在機庫裡出現兩個一樣的名字。
- **避開日文和製漢字與異體字**：字型（Noto Sans TC／Chiron GoRound TC／LXGW WenKai TC）
  不保證有字符，缺字會變豆腐方塊或跳字型，整排字看起來歪掉：

  ```
  禁用：凪 雫 咲 凜 澪 燐 朧 縭 々 ヶ 雛 繋
  ```

  （`凜`／`澪`／`凪` 同時是模型取日本名時的高頻濫用字 → 雙重禁用。）
- 建議改用台灣常見字：`霜 月 影 刃 霞 蓮 雀 蒼 焰 織 夜 星 鈴 澄 颯 瞳`。
- 同一批六台**不要共用同一個字**（不要六台都叫「X月」「X刃」）。

### 13.5 其他文案

- `quote`／`lore` 用繁體中文台灣用語；`lore` 一到兩句就好，不要寫成設定集。
- 不要出現真實品牌、真實人名、其他作品的名詞或招式名。
- 標點：中文句子用全角（，。！？）；括號內的英文用半角。
